Five-person Core pilot: release runbook

Prepared for the existing hosting setup. The owner will supply deployment instructions later. Nothing in this document deploys the service or activates live in-app payments.

Release scope

One installation, isolated client workspaces, hidden Sydekyks managed AI, client BYOK, Credits, no-email setup and account recovery, built-in LMS, global and private courses, exams and independent certification. Platform Trainers operate only their assigned Partners and clients. Core payments and refunds remain external and manual.

Manual billing must be explicit in the deployed environment. The Stripe test adapter is for test environments only. A paid enrollment requires the Sydekyks operator to verify the external receipt; a Trainer cannot create a paid training entitlement.

What the deployment owner supplies

  1. Existing hosting location, public HTTPS domain, DNS and reverse-proxy configuration.
  2. Existing database/Redis configuration, private API-to-worker routing, durable volume paths and secret-store locations.
  3. Backup destination, encryption and restore access, plus monitoring/alert destination and named operator.
  4. Approved change window, maintenance/rollback procedure and the exact tested image reference for both API and worker.

Use release.env.example as the pilot requirements overlay. Keep encryption keys, JWT secret and operator allowlist in the approved secret store. Preserve the original encryption key with every restorable database backup.

Before switching traffic

  1. Freeze the source revision and image digest after build, automated checks, runtime rehearsal and the internal-browser role review. Record unresolved findings explicitly.
  2. Take a coordinated backup: stop new admissions, drain work, retain paused/uncertain records, stop API and workers, snapshot PostgreSQL and the relevant Redis state, then restart the same release. Keep backups and key material encrypted with access separate from normal app users.
  3. Restore that snapshot to isolated infrastructure with outbound email, payments and supplier calls disabled. Restore the same encryption key; use separate network endpoints. Do not point a restore at the live Redis namespace.
  4. Compare identity/role/enrollment/attempt/certificate/grant and liability counts; verify encrypted connection readability without printing secrets; read representative file bytes. Run a sample workflow in the restored system and confirm one charge.
  5. Record backup timestamp, restore start/end, verification result and measured recovery time. Operational targets: backup age at most 24 hours and restoration within 4 hours. Schedule backups through the existing infrastructure; a local rehearsal does not prove that schedule.
  6. Put the public hostname behind HTTPS, confirm proxy/body/rate limits, secure cookies, allowed origins and the private worker connection, then repeat sign-in and setup-link checks at the public origin.

Storage and capacity

Starter / Team1 GiB / 4 GiB
Installation file footprint8 GiB

Caps are configurable in bytes. Actual retained database file bytes are measured; replacement only charges the size difference. At capacity, new executions and growing uploads stop while reads, shrinking files, support and recovery remain available. Temporary files are reclaimed after retention only when their project has no unsettled execution root or nonterminal run. Saved samples and durable assets are retained.

The global operator endpoint GET /v1/hosting/operator/storage reports retained file usage and total PostgreSQL database bytes. File caps exclude indexes, WAL, logs and backups. Monitor host disk separately: alert at 70% used and urgently at 80%; keep at least twice the file cap plus database/WAL/backup headroom. Notify the named operator on unhealthy API/worker, failed backups, storage warnings, stale pricing or held AI liabilities. Never resolve an uncertain supplier request by blindly sending it again.

Account recovery without email

A global Sydekyks operator verifies the person using an existing trusted contact method, opens Platform → Account recovery, looks up the exact email and records a short reason and verification note. Do not paste passwords, keys, ID scans or private documents into those notes. Issue the private 30-minute link and share it through the verified channel. Reissue invalidates the previous link; revoke cancels it.

The participant chooses the password. Successful recovery invalidates old sessions, outstanding email codes and MCP tokens, and consumes the link once. It does not alter workspace roles, enrollment, certification, Credits or billing. Recovery of platform operators, team staff and Trainers uses the existing privileged break-glass procedure; this customer recovery screen cannot reset them.

Days 61–90 of Core assessment

Core includes 60 days of training workspace access and 90 days to complete assessment. Between days 61 and 90, an independent Sydekyks assessor can activate one limited assessment grant in the learner’s existing private home: 100 execution Credits and US$1 of managed supplier allowance in total, concurrency one, ending at the original assessment deadline. It cannot renew or be enlarged through the monthly allowance control. Trainers cannot activate it or certify their learners. Course reading continues for the original course-access period.

Calendar renewal required: the current approved managed-pricing calendar stops at 1 January 2027 UTC. A Core cohort starting 19 October has an assessment deadline around 17 January. Book any managed-AI assessment before the cutoff, or install the next verified supplier calendar and obtain a fresh pricing approval before 1 January. Assign the operator a 15 December reminder and verify the calendar before promising January managed service. Merely extending the approval timestamp is prohibited; beyond verified coverage, managed calls stop safely.

Rollback and launch records

Accounting, recovery, assessment and training histories are durable. Several migrations deliberately reject rollback once populated. Roll back using the verified image/database/Redis/key snapshot as a coordinated set during maintenance; do not delete ledger rows or apply an older binary to a newer schema without compatibility evidence. Reconcile all changes made after the snapshot before reopening access.

Before inviting the five paid participants, the owner names the manual payment/refund verifier, support contact, Trainer and independent assessor, publishes the reviewed real course/question bank, books included coaching capacity and approves Partner/client terms and the commission register. Technical test accounts and synthetic receipts prove application behavior; they do not prove money collection or learning quality.
