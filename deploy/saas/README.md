# Hosted SaaS MVP deployment

This opt-in deployment is separate from the default free self-hosted Compose file. Never enable hosted mode on an existing unmarked self-hosted database.

MVP policy: manual billing, manual account provisioning, no Stripe keys or automatic public signup. The website sends access requests to the team. Production starts with a new PostgreSQL database; local rehearsal accounts remain local. Platform admins configure the managed provider and approve pricing through the admin UI. Client/Partner BYOK is tenant-scoped; assigned Partners cannot access Sydekyks-wide supplier credentials or client billing.

Copy `compose.yaml`, a private `production.env`, and Caddy configuration to the server. `production.env` must be root-owned 0600, outside public assets/source archives. Set a reviewed immutable `SYDEKYKS_IMAGE`, fresh encryption/JWT/database secrets, `AP_SERVICE_MODE=hosted`, `AP_HOSTED_BILLING_MODE=manual`, explicit `AP_HOSTED_OPERATOR_IDENTITY_IDS`, public frontend URL, PostgreSQL/Redis, SANDBOX_CODE_ONLY, DB storage, and conservative worker concurrency. Never copy test Stripe keys or development supplier credentials by default.

Build with `docker build --build-arg SYDEKYKS_RELEASE_VERSION=1.1.0 --build-arg SYDEKYKS_SOURCE_REVISION=<commit> -t <immutable-image> .`. The release argument is required by runtime staging. Use BuildKit. Verify distribution boundaries and runtime resolution during the build.

Run `docker compose --env-file production.env up -d` from this directory. PostgreSQL and Redis have no published host ports. Only the app's loopback port 8080 is exposed; Caddy terminates public HTTPS on ports 80/443 and supports streaming/WebSockets. Keep 22/tcp for authorized SSH. Block public signup paths at ingress for this manual MVP. Password/setup-link authentication remains available.

Initialize only the nominated platform administrator after normal migrations. Use the application's password hasher and a verified identity matching the explicit operator allowlist. Never bypass accounting/bootstrap guards or seed paid grants. Provision clients/Partners with normal audited admin APIs/UI after payment is recorded.

On startup, verified allowlisted operator-owned trial homes receive an internal allocation of 100,000 Credits per UTC month anniversary. This uses distinct `operator:` provenance and Growth resource ceilings, without creating a paid subscription. Refreshes do not refill the current month. Old trial charges/holds remain historical; later settlement remains possible. Suspensions, independent funding and explicit expiration overrides are preserved. A new operator home created after startup enrolls at the next restart. Partner and client allowances are unchanged.

Hosted Ask Syd builds real Mission drafts and Tables through an admitted-project internal tool bridge. Static catalogue schemas do not run dynamic supplier callbacks. Stored-data reads require approval before later mutations. Chat-driven test runs, publication, raw actions and remote MCP remain excluded from this bridge; test/publish a saved draft in its editor. Internal `ap_*` and `@activepieces/*` identifiers remain compatible, while customer explanations use Sydekyks terminology.

Hosted draft-form submissions require a signed-in user with run permission for that exact workspace. They start one ordinary metered test run; public published forms keep their existing registered-trigger path. A queued acknowledgement is not proof the Mission succeeded: inspect Run History and the saved output.

AI text actions default to Sydekyks for new configurations. DeepSeek appears as a client BYOK option only when an eligible client key exists; shared managed credentials are never advertised as BYOK. Preserve explicitly saved BYOK selections. Chat attachments use private, expiring Sydekyks file IDs. Ordinary Form-upload URLs are not these IDs: a trusted Form-upload-to-AI ingestion adapter remains an open gap. Do not claim uploaded-résumé scoring is wired by placing a URL in `fileIds`; résumé text is the currently supported form alternative.

Open authentication gap: operator-assisted one-time recovery links work at `/platform/account-recovery`; public self-service email password reset is not complete. The legacy reset form targets an absent route and must not be presented as working simply because SMTP is configured.

Internal AI transport uses a bounded 1 MiB envelope and an authenticated workspace rate bucket of 240 calls/minute, separate from sign-in/IP throttling. Hosted model history and tool outputs are preserved without heuristic truncation; preflight allows 512 KiB of history/new text, leaving transport room for instructions and schemas. Larger calls reserve the approved input/output context ceiling (including attachments), then settle verified actual usage. Conservative holds can require more available Credits; this is not an unlimited-context promise. The 26 October policy removes the separate fixed 32-model-call ceiling, including managed/BYOK native AI calls. Funding and per-run spending checks still precede each supplier dispatch; supplier-budget, time, cancellation, concurrency, context and user-configured Agent-step safeguards remain. Native search/page-read-specific budgets and tool limits are separate. BYOK never falls back to the shared managed key. Versioned pre-dispatch receipts at the pinned internal completion endpoint identify known size/rate refusals; unknown supplier outcomes remain uncertain. Never resolve a hold from HTTP status alone or manually reset grant/concurrency counters. Recovery of historical uncertain roots requires reviewed evidence and an audit record, followed by the normal ledger reconciliation. Preserve queued jobs and original run/idempotency identifiers: temporarily freeze public ingress, preserve and pause all four durable queues (workerJobs, runsMetadata, barrierEvaluation and system-job-queue), drain active work, stop the old API/background writers, take a stable PostgreSQL/Redis/config backup, verify an off-server copy and isolated restore, replace only the app, verify existing row hashes and pending job identities/payloads/attempts before activation, then restore each queue’s original pause state and ingress. Rollback must also re-pause and drain before replacing any app that may have resumed work. Unknown historical holds require their own evidence-based review and are not cleared as part of deployment. Do not resend or clone queued work.

For a reviewed backend-only hotfix with no dependencies, assets or configuration changes, `scripts/package-backend-patch.mjs BASE_REVISION sha256:BASE_IMAGE_ID NEW_PRIVATE_DIRECTORY` packages compiled JavaScript over the exact immutable deployed image. Source must be clean/committed and compiled first. It rejects unsupported changes and writes a source/base/file-checksum manifest. Build that directory with Docker, retain the previous image, take an encrypted backup, update only the image setting in the server's existing environment, and recreate only the app service. Do not upload a stale local production.env. A full Dockerfile build remains the canonical release path; a backend patch must never copy local native modules or skip runtime/worker checks.

For a reviewed browser-source hotfix, append `--include-web` explicitly. The default mode still rejects frontend changes. This mode allows only web `src` TypeScript/TSX and web test changes in addition to the backend allowlist; dependency, build-configuration and deletion changes require a full image build. It requires clean committed source throughout, checks backend emit freshness and refuses uninspected symlinks. Packaging deletes generated web output, runs a fresh local Vite production build with source maps disabled, and packages the complete `dist/packages/web` tree with every file checksum in the `backend+web` manifest. Its Dockerfile removes the old web directory before copying the new tree, preventing stale chunks from surviving. Local `node_modules` are used only to build and are never copied. Retain all normal base-image, backup, queue-drain and runtime verification gates; this flag does not authorize deployment by itself.

Acceptance: HTTPS validity, sign-in, operator authorization, manual billing, no public signup, installed accounting/LMS migrations, catalogue availability, online worker with the current hosted accounting capabilities, and a real bounded run after production managed AI is configured. A successful HTTP health check alone is insufficient.

Back up PostgreSQL with `pg_dump -Fc`, Redis with a coordinated persistence snapshot, app assets, production.env and encryption keys. Backups are private; restore to a separate database and verify before switching. Do not delete volumes or replace encryption keys during upgrades. Keep the previous image/config and take a backup before migrations; reverse migrations are not assumed safe. An off-server encrypted backup destination and a restore drill remain explicit operational requirements.

Small servers: one worker is a starting setting, not a capacity promise. Measure API/worker RSS, swap and queue latency under the intended load. Recommend at least 4 GB RAM for the hosted stack; scale only after measuring catalogue, files, concurrent chats and workflow runs.

The hosted image builds and stages the reviewed `manual-trigger`, `ai`, and `mcp-client` Gadgets. Set `AP_DEV_PIECES=manual-trigger,ai,mcp-client` to select these bundled versions while retaining `AP_PIECES_SYNC_MODE=OFFICIAL_AUTO` for the rest of the catalogue. This existing loader setting selects the prebuilt code; the development file watcher is disabled in production. Do not replace these Gadgets with newer external npm versions until their hosted accounting paths have been reviewed.

`backup.sh` and the accompanying systemd service/timer implement daily age-encrypted server backups (14-day local retention). Install `age`, generate a dedicated recovery identity, retain only its public recipient at `/opt/sydekyks/backup-recipient.txt`, save the private recovery identity off-server, and verify a separate-database restore before enabling the timer. Keep copying encrypted snapshots to an off-server destination; this timer alone does not provide off-server delivery. Scripts assume this Compose project/container naming and must be installed root-owned.
